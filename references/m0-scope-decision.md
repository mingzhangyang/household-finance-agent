## 决定 1：首发用途

| 选项 | 含义 | 对后续工作的影响 |
|---|---|---|
| A. 个人研究（此前暂定基线） | 负责人本人或懂行的用户比较假设，不面向第三方家庭 | 维持研究等级；M5 的隐私与支持流程可以从简 |
| B. 专业人员辅助 | 由具备资质的人员使用并复核输出 | 需要指定复核人、问题记录和版本回退流程（M5） |
| C. 受控家庭试用 | 真实家庭在复核下使用 | 需要 M5 全部门槛：隐私、支持、问题分级、旧报告重新生成 |

**决定：B。**

影响：
- 报告和 Skill 的目标读者是专业人员。输出仍须写明适用范围、未建模事项和验证状态，不能因为“有专业人员复核”就省略限制说明。
- 当前代码：`evidence_status.model = restricted_research`，`professional_review = not_recorded`。在 M5 建立逐份报告的复核记录机制之前，这两个值不变；复核人对规则和案例的意见先记录在验证证据中。
- M5 需要：问题分级与记录、规则或代码出错时的版本回退、受影响旧报告的重新生成。

## 决定 2：支持的家庭、州、账户和收入

| 子项 | 暂定基线（当前代码） | 可选项与影响 |
|---|---|---|
| 2a 报税身份与年龄 | 单身或夫妻合并申报；出生 1951–2006；家庭成员和报税身份不变 | 保持；或增加户主（HoH）、夫妻分别申报等，每项都需要新税表、案例和验证器扩展 |
| 2b 州所得税 | 不支持任何州，报告注明未计算州税 | **A. 仅联邦**：可作为受限工具发布，但不能宣称算出家庭完整税负；**B. 纳入一个州（写明州名）**：M2 增加该州所得税 |
| 2c 应税经纪账户 | 最多一个；只在卖出时按比例成本计算正的长期收益；除现金利息外不计股息和利息，亏损不抵扣 | **A. 首发家庭基本不持有**：保持受限并继续披露；**B. 首发家庭持有**：必须做股息和利息的逐年计税、资本损失抵扣与结转，以及它们对 NIIT 的影响 |
| 2d 收入类型 | 工资、养老金、外部估计的社保、税后净额事件收入；不支持自雇和租金 | 保持；或逐项增加，每项都要贯穿税务、提款、账本、报告和验证器 |
| 2e 账户类型 | 现金、应税、传统 IRA/401(k)、Roth IRA；不支持继承账户、8606 税后基础、雇主匹配和追加缴款 | 保持；或增加，例如追加缴款（Notice 2025-67：2026 年 8,000 美元，60–63 岁 11,250 美元） |

**决定：** 2a 沿用基线；**2b B，Maryland，并保留其他州的可操作性**；**2c B**；2d 沿用基线；2e 沿用基线。

2b 的工程含义：
- 州税做成按辖区登记的接口：输入写明辖区、全年居民身份和（Maryland 必需的）县或 Baltimore City；未登记的辖区、非全年居民、缺少县别时一律拒绝，不以零代替。
- 只提供联邦税的研究用法（`excluded_with_disclosure`）继续保留，报告照旧注明未计算州税。
- Maryland 从联邦 AGI 起算再做州的加减项，所以先完成 2c（它改变联邦 AGI），再做 Maryland。
- Maryland 规则须按税年登记、读官方原文（Comptroller of Maryland 的表格说明、地方税率表和州法条文）并补印刷表或官方算例；与联邦规则一样把已公布年份和推算年份分开标注。
- 再增加一个州时，只需新增该州的规则登记、引擎模块、验证器副本和案例，不改主引擎的资金求解流程。

2c 的工程含义（M2 第一组）：
- 应税账户每年的合格股息、非合格股息、应税利息和资本利得分配必须作为明确输入（可以为零，但不能缺省），并逐年计税；再投资部分计入成本基础。
- 卖出可以实现亏损；净资本损失每年按上限抵减普通收入，剩余部分结转；期初已有的结转额是必填输入。
- NIIT 的投资收入包括上述股息、利息和净收益；合格股息与长期收益一起适用优惠税率。
- 贯穿输入、税额、提款求解、账本、报告和独立验证器，并补充独立 Decimal 案例。

## 决定 3：社保

| 选项 | 影响 |
|---|---|
| A. 外部提供、与选定领取年龄对应的估计（此前暂定基线，引擎当前执行） | 不改变 M3 计划；领取年龄改变时须提供新的估计 |
| B. 首发阶段即从收入记录重建 | M3 范围扩大，需要 SSA 收入记录、指数化与更多独立案例 |

**决定：B。**

影响（M3）：
- 新输入：每人的 SSA 收入记录（逐年社保覆盖收入），来自 SSA 账户或 Statement；只记录证据 ID，不在仓库中保存真实记录。
- 新规则数据：平均工资指数（AWI）、各资格年份的折点、COLA、最高应税收入、满额退休年龄表；按年份登记，已公布与推算分开标注（沿用 M2 第一项的做法）。
- 计算链：指数化收入 → 最高 35 年 → AIME → PIA（取整规则）→ 资格年份之后的 COLA → 按月的提前/延迟领取调整；再做配偶与遗属福利、家庭上限，避免重复计算。
- 现有 `ssa_benefits.py` 的 PIA 与领取调整是候选主接口；`social_security.py` 在确定主接口时做一致性测试后再决定适配或退役。
- SSA Statement 上的估计值改为**独立对照**，与重建结果比较，差异须解释；在 M3 完成之前，引擎继续使用现有的“外部提供估计”路径，并在报告中标明这是过渡做法。
- 收入检验（未到满额退休年龄仍工作且领取）目前被拒绝；若首发家庭需要，须作为 M3 的单独事项建模。
- 原文核对：SSA 的 Federal Register 公告（AWI、折点、COLA、工资上限）和 20 CFR Part 404；`www.ssa.gov` 网页在当前云环境返回 403，需放行或改用 Federal Register 与 eCFR 的可访问版本。

## 决定 5：交付方式

| 选项 | 影响 |
|---|---|
| A. 本地离线（此前暂定基线） | HTML 报告含明文财务数据，由用户自行保管 |
| B. 托管或多人访问 | 需要另行设计存储、权限、日志和删除流程，作为 M5 的隐私门槛 |
| C. 作为 AI agent / Skill 在 Codex 或 Claude Code 中运行（负责人新增） | 见下 |

**决定：C。**

影响：
- **运行方式**：仓库本身就是一个 Skill（`SKILL.md` 带 `name`/`description`，Codex 另读 `agents/openai.yaml`）。安装位置：Codex 读取仓库或用户目录下的 `.agents/skills/<name>/`，Claude Code 读取 `.claude/skills/<name>/` 或 `~/.claude/skills/<name>/`；两者都支持指向本仓库的符号链接。宿主 agent 通过自己的命令行工具运行仓库脚本；所有财务数字只能来自脚本输出，模型不自行计算或改写数字（`SKILL.md` 规则不变）。
- **隐私边界**：计算在本地或宿主的会话环境中执行，但 agent 读入上下文的方案 JSON、结果和对话内容会发送给所用模型的提供方（Codex 为 OpenAI，Claude Code 为 Anthropic），并受用户账户的数据保留设置约束；在云端会话中，仓库和生成文件还位于提供方的容器内。因此不能再称“完全本地离线”。M5 的隐私检查须覆盖：agent 读入哪些字段、如何最小化（别名、不含账号/SSN）、生成的 HTML 报告仍含明文数据。
- **双宿主验收**：M5 增加在 Codex 和 Claude Code 中各走一遍 validate → run → verify → render → trace 的端到端流程（虚构数据），记录宿主版本和结果。
- **措辞**：`SKILL.md`、README 和隐私说明不再写成只由 ChatGPT 协调，改为宿主中立的“宿主 agent”。

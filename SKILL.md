# Household Finance Agent — audited restricted engine v2.1

Use ChatGPT as the coordinator and code-based tools as the ONLY author of calculated financial results. Never invent financial figures, tax rules, proof of source verification, or simulated probabilities. A financial report may look professional while still having inappropriate assumptions; **numeric model restrictions outrank visual polish**.

## Mandatory operating rules

1. **Identify jurisdiction and planning question.** The audited v2.1 calculator is restricted to US federal tax assumptions, one single filer or two married joint filers, dollar balances as of December 31, 2026, annual projections starting 2027. Opening balances are explicitly projected or documented as of 2026-12-31; do not claim actual year-end statements exist before that date. Other situations require explanation, not a silent fallback.
2. **Create a source register.** For every material input, record origin, statement date, whether user-supplied, estimated, fictional, or documented. Never label invented sample balances as user finances. Use `input_provenance` in v2 JSON, and cite document IDs rather than embedding SSNs, complete account numbers or credentials. See `references/audited-data-contract.md`.
3. **Fail closed.** Reject missing taxable cost basis, account ownership, uncertain IRA after-tax basis, Roth distribution qualifications, exceptional RMD tables, unmodeled early withdrawals, working-and-claiming Social Security earnings tests, missing tax jurisdiction or unsupported event income. Do not convert unknown fields into silent zeros. Check `scripts/audit_plan.py validate` before running.
4. **Separate current law from future assumptions.** IRS 2026 schedules are the reference year. The 2027+ schedules are *hypothetical inflation-indexed assumptions* except explicitly noted SSA's already published 2027 wage base. No future tax law is asserted. See `references/rules-provenance.md`. Re-check official guidance if a calculation is used for an actual decision.
5. **Run the audited engine and independent verifier.** Never deliver a high-stakes conclusion unless both run and output-only verifier pass. Use the command sequence below. A missing or failed verification result must be conspicuous in the report.
6. **Explain exact accounting, not just percentages.** Report key numbers with input SHA256, engine SHA256, ruleset version, underlying assumptions, tax-bracket arithmetic, one reproducible annual ledger and count of satisfied Monte Carlo paths. Name Wilson's interval a *sampling* interval only; the model is not calibrated to real-world outcomes.
7. **Prefer the private, interactive audit webpage** generated by `scripts/render_audit.py`. Its JavaScript only visualizes precomputed Python outcomes, and **does not implement a second conflicting tax engine**. Scenario changes are prepared and recomputed in Python; in-browser control is scenario switching, per-year drilldown, path-manifest inspection and CSV/JSON exports, not live tax calculation. To change a custom assumption, update the input plan and regenerate HTML.
8. **Disclose limits and request professional review** before any irreversible decision. Do not file taxes, recommend a specific dollar Roth conversion, transfer funds or place a trade. State unsupported: state/local income tax, IRMAA, NIIT, ACA, detailed filing forms, dynamic SSA benefits, spousal survivorship, mortality, debt, ordinary taxable dividends, historical market calibration and many specialized planning cases. See `references/audit-methodology.md`.
9. **Control user data.** Never put authentic financial data or a generated HTML file on a public site without explicit consent. A private offline HTML file is not encrypted. Do not claim the Skill stores or automatically refreshes balances.

## Reproducible v2.1 workflow

From the skill root, with Python 3.10+:

```bash
python scripts/audit_plan.py validate examples/audited-household-2026.json
python scripts/audit_plan.py run examples/audited-household-2026.json --output result.json
python scripts/verify_outputs.py result.json --plan examples/audited-household-2026.json --engine-dir scripts --output verification.json
python scripts/render_audit.py examples/audited-household-2026.json --output financial_audit_dashboard.html
python scripts/audit_plan.py trace examples/audited-household-2026.json --path-index 17 --output path17.json
python -m unittest discover -s tests -v
```

The example is explicitly **fictional**. `run` emits deterministic account-level and tax-bracket ledgers, 300 seeded Monte Carlo path summaries, sampling interval, tax-policy citation links and code/data fingerprints. `trace` reconstructs a specified random path's full annual ledger. `verify_outputs.py` independently checks output arithmetic without importing the financial simulator. Browser test: `python tests/test_audit_browser.py`, when Playwright and Chromium are installed.

For scenario comparisons, require equal year range, random seed and path count so the same stochastic paths are used:

```bash
python scripts/audit_plan.py compare baseline-v2.json alternate-v2.json --output comparison.json
```

For the default visual report, `render_audit.py` creates four independently precomputed scenarios: baseline, first person retiring three years sooner, spending increased 10%, and lowered returns. Explain the change in each scenario.

## Data and report traceability checklist

- Confirm all material inputs have provenance or are explicitly marked *unverified* / *fictional*; `documented_verified` requires documentary references for each core monetary field but **does not certify the underlying documents**.
- Verify household annual identity: `closing = opening + investment growth + external income − living paid − taxes paid`.
- Verify **each account** using all contribution, RMD, conversion, optional draw, cash receipt and cash expense journal entries. Disclose rounding differences separately from unrounded computational reconciliation.
- Verify income tax lines equal the sum of ordinary progressive brackets plus stacked capital-gains bands; payroll tax components and RMD divisors reconcile independently.
- Verify every Monte Carlo headline against per-path summaries; replay any selected path using its index and the saved seed. Never call model success share an empirically validated forecast.
- Label missing law/inputs accurately. A report cannot use the words “certified,” “IRS-validated,” “CPA-approved” or “RightCapital-equivalent” without independent evidence.
- When no code tools are accessible, explain inability to audit; do not fabricate passing tests or a download file.

## Experimental professional reference components (feature branch)

Use these only for scoped independent checks, NEVER silently inject their outputs into `audit_plan.py`:

- `scripts/tax_extensions.py`: IRS 2026 NIIT on independently documented MAGI/net-investment income, not yet integrated into the cash-funding solver.
- `scripts/social_security.py`: official 2026/2027 eligibility-year PIA bend points, FRA and worker claiming factors; AIME and COLA-adjusted PIA remain external inputs, no spousal/survivor calculations. See `references/ssa-methodology.md`.
- `scripts/lifecycle.py`: explicit deterministic death-year, spending and total survivor-household SSA assumption schedule; no mortality rates or post-death tax modeling.
- `scripts/market_history.py`: reads sourced stock/bond annual return CSV, computes sample moments and rolling historical funding windows; a 19-year, two-decimal example is a smoke fixture, not professional market calibration. See `references/market-data-provenance.md`.

When the user asks for a decision-grade retirement outcome, first consult `references/professional-validation-gates.md`; report **not validated** while integration, external benchmarking and audited historical source data remain incomplete. Never cite an optional reference module as evidence the main projection has incorporated it.

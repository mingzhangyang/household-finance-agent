# Household Finance Agent — audited restricted engine v2.2

Use the host agent (Codex or Claude Code) as the coordinator and the bundled scripts as the ONLY author of calculated financial results. Never invent financial figures, tax rules, proof of source verification, or simulated probabilities. A financial report may look professional while still having inappropriate assumptions; **numeric model restrictions outrank visual polish**.

## Mandatory operating rules

1. **Identify jurisdiction and planning question.** The audited v2.2 calculator is restricted to US federal tax assumptions, one single filer or two married joint filers, dollar balances as of December 31, 2026, annual projections starting 2027. Opening balances are explicitly projected or documented as of 2026-12-31; do not claim actual year-end statements exist before that date. Other situations require explanation, not a silent fallback.
2. **Create a source register.** For every material input, record origin, statement date, whether user-supplied, estimated, fictional, or documented. Never label invented sample balances as user finances. Use `input_provenance` in v2 JSON, and cite document IDs rather than embedding SSNs, complete account numbers or credentials. See `references/audited-data-contract.md`.
3. **Fail closed.** Reject missing taxable cost basis, a taxable account without stated dividend/interest/capital-gain-distribution yields (zero is allowed, silence is not) or without `capital_loss_carryover_into_2027`, a pension without an explicit start age, account ownership, uncertain IRA after-tax basis, Roth distribution qualifications, exceptional RMD tables, unmodeled early withdrawals, working-and-claiming Social Security earnings tests, missing tax jurisdiction or unsupported event income. Do not convert unknown fields into silent zeros. Check `scripts/audit_plan.py validate` before running.
4. **Separate current law from future assumptions.** Each year uses published values where they exist (IRS 2026 tables; SSA's published 2026 and 2027 wage bases); other years are *hypothetical projections* from the latest published year, labeled `projected` in every row's `rule_basis` and in the report's year audit. No future tax law is asserted. See `references/rules-provenance.md`. Re-check official guidance if a calculation is used for an actual decision.
5. **Run the audited engine and independent verifier.** Never deliver a high-stakes conclusion unless both run and output-only verifier pass. Use the command sequence below. A missing or failed verification result must be conspicuous in the report.
6. **Explain exact accounting, not just percentages.** Report key numbers with input SHA256, engine SHA256, ruleset version, underlying assumptions, tax-bracket arithmetic, one reproducible annual ledger and count of satisfied Monte Carlo paths. Name Wilson's interval a *sampling* interval only; the model is not calibrated to real-world outcomes.
7. **Prefer the private, interactive audit webpage** generated by `scripts/render_audit.py`. Its JavaScript only visualizes precomputed Python outcomes, and **does not implement a second conflicting tax engine**. Scenario changes are prepared and recomputed in Python; in-browser control is scenario switching, per-year drilldown, path-manifest inspection and CSV/JSON exports, not live tax calculation. To change a custom assumption, update the input plan and regenerate HTML.
8. **Disclose limits and request professional review** before any irreversible decision. Do not file taxes, recommend a specific dollar Roth conversion, transfer funds or place a trade. State unsupported: state/local income tax, IRMAA, Form 8960 deductions and foreign MAGI adjustments, ACA, detailed filing forms, tax lots, wash sales and short-term holding periods, dynamic SSA benefits, spousal survivorship, mortality, debt, historical market calibration and many specialized planning cases. The capital-loss carryover adds back the 2025–2028 senior deduction under IRC 1212(b); say that this reading awaits professional review whenever it changes a carryover. See `references/audit-methodology.md`.
9. **Control user data.** Never put authentic financial data or a generated HTML file on a public site without explicit consent. A private offline HTML file is not encrypted. Anything you read into the conversation (plan JSON, results, statements) is sent to the host's model provider; read only the fields you need and use account aliases, never full account numbers or SSNs. Do not claim the Skill stores or automatically refreshes balances.

## Reproducible v2.2 workflow

From the skill root, with Python 3.10+:

```bash
python scripts/audit_plan.py validate examples/audited-household-2026.json
python scripts/audit_plan.py run examples/audited-household-2026.json --output result.json
python scripts/verify_outputs.py result.json --plan examples/audited-household-2026.json --engine-dir scripts --output verification.json
python scripts/render_audit.py examples/audited-household-2026.json --output financial_audit_dashboard.html
python scripts/audit_plan.py trace examples/audited-household-2026.json --path-index 17 --output path17.json
python scripts/verify_outputs.py path17.json --plan examples/audited-household-2026.json --trace --trace-result result.json
python -m unittest discover -s tests -v
```

The example is explicitly **fictional**. `run` emits deterministic account-level and tax-bracket ledgers, 300 seeded Monte Carlo path summaries, sampling interval, tax-policy citation links and code/data fingerprints. `trace` reconstructs a specified random path's full annual ledger. `verify_outputs.py` independently checks output arithmetic and recomputes the restricted federal worksheet steps from register values retyped in the verifier; with the plan it also re-derives timing, returns, RMD/conversion schedules, funding order and shortfall legitimacy, and `--trace` regenerates a traced path's returns. It never imports the financial simulator, and it does not certify that the rules or conventions suit a household. The checked-in Node.js handler test (`tests/report_ui.cjs`, invoked by `tests/test_report.py`) checks report status and exports with a minimal DOM; it is not a full browser layout test.

For scenario comparisons, require equal year range, random seed and path count so the same stochastic paths are used:

```bash
python scripts/audit_plan.py compare baseline-v2.json alternate-v2.json --output comparison.json
```

For the default visual report, `render_audit.py` creates four independently precomputed scenarios: baseline, first person retiring three years sooner, spending increased 10%, and lowered returns. Explain the change in each scenario.

## Data and report traceability checklist

- Confirm all material inputs have provenance or are explicitly marked *unverified* / *fictional*; `documented_verified` requires documentary references for each core monetary field but **does not certify the underlying documents**.
- Verify household annual identity: `closing = opening + investment growth + external income − living paid − taxes paid`.
- Verify **each account** using all contribution, RMD, conversion, optional draw, cash receipt and cash expense journal entries. Disclose rounding differences separately from unrounded computational reconciliation.
- Verify income tax lines equal the sum of ordinary progressive brackets plus the selected capital-gain calculation (preferential stacking or the lower ordinary-rate cap); separately recompute the 3.8% NIIT from modeled interest, ordinary dividends and the Form 1040 line 7a capital gain or allowed loss, household MAGI threshold, and its dedicated fields. For a taxable account, check distributions, basis, Schedule D netting, the $3,000 loss limit and the carryover chain. Recheck payroll tax and RMD divisors independently.
- Verify every Monte Carlo headline against per-path summaries; replay any selected path using its index and the saved seed, and verify it with `verify_outputs.py --trace`. Never call model success share an empirically validated forecast.
- Label missing law/inputs accurately. A report cannot use the words “certified,” “IRS-validated,” “CPA-approved” or “RightCapital-equivalent” without independent evidence.
- When no code tools are accessible, explain inability to audit; do not fabricate passing tests or a download file.
